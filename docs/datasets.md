# Datasets

## Current defaults and prompt roles

The default configuration uses `mlabonne/harmless_alpaca` and
`mlabonne/harmful_behaviors`, with the `text` column. It does not automatically
download or include the historical bilingual `good_*` / `harmful_*` corpora.
The four prompt sources have distinct roles:

| Config section | Used for | Default split |
|---|---|---|
| `benign_prompts` | Benign hidden states for vector extraction | `train[:400]` |
| `target_prompts` | Target hidden states for vector extraction | `train[:400]` |
| `benign_eval_prompts` | Damage/coherence measurements during trial scoring | `test[:100]` |
| `target_eval_prompts` | Refusal measurements during trial scoring | `test[:100]` |

The evaluation sources influence trial selection; they are not an independent
final test set. Reserve a separate, unseen set for final reporting. Dataset
names do not determine their role: historical model recipes explicitly selected
different slices of the same local corpus for extraction and trial scoring.

Chinese or mixed-language coverage requires actually supplying those prompts.
Chinese refusal-detection phrases alone do not add Chinese evaluation coverage.
Results from one corpus must not be presented as reproduction of results from
another corpus.

## Historical bilingual corpora and availability

The historical dataset location is
[wangzhang/abliterix-datasets](https://huggingface.co/datasets/wangzhang/abliterix-datasets).
It is currently not publicly retrievable in our access check (2026-11-01).
That does not establish whether it was deleted, made private, or otherwise
restricted. These files are not included in this repository: `/datasets/` is
git-ignored, and paths such as `datasets/good_1000` in older recipes refer to
local files that must be supplied separately. A Git checkout does not restore
them.

The exact filenames and SHA256 values required by HonestAbliterationBench are
recorded in [benchmarks/SPEC.md](../benchmarks/SPEC.md). Hashes identify the
original artifacts; they cannot reconstruct their contents. A newly generated
or substituted corpus is a different benchmark and needs its own provenance
and results.

| Dataset | Count | Description |
|---------|-------|-------------|
| `good_500` | 500 | Historical harmless prompt subset |
| `good_1000` | 1000 | Harmless prompts — full set |
| `harmful_500` | 500 | Historical harmful prompt subset |
| `harmful_1000` | 1000 | Harmful prompts — full set |

The following design descriptions refer to those historical corpora, not to
the public defaults or a guarantee of current artifact availability.

## Video-model datasets

`video_good_1000` / `video_bad_1000` (historically hosted in the same dataset
repository, subject to the availability limitation above) are **text-to-video
(T2V) scene-description prompts** rather than chat instructions, generated by
[`scripts/generate_video_prompts.py`](../scripts/generate_video_prompts.py).
They are not part of HonestAbliterationBench and are not SHA256-pinned by
[benchmarks/SPEC.md](../benchmarks/SPEC.md).

| Dataset | Count | Description |
|---------|-------|-------------|
| `video_good_1000` | 1000 | Should-generate T2V scene prompts (698 matched counterexamples + 302 everyday) |
| `video_bad_1000` | 1000 | Should-refuse T2V scene prompts across 14 categories (violence, weapons, self-harm, drugs, CBRNE, hate speech, extremism, harassment, sabotage, property destruction, animal cruelty, dangerous stunts, disinformation/deepfake, nudity & sexual content) |

Generation uses a hard policy floor: no minors in any unsafe/sexual/violent role, no real identifiable individuals, and sexual content kept non-graphic. The generator also rejects provider refusal boilerplate, unsafe prompts that mention minors, and duplicate outputs before writing a row. Category counts aren't perfectly uniform — Gemini's own safety filter blocks some categories (notably CBRNE) far more than others regardless of the research framing.

## Why we built our own datasets

Public abliteration benchmarks (e.g. `mlabonne/harmful_behaviors`, `mlabonne/harmless_alpaca`) are widely used but have critical limitations:

- **English-only**: zero coverage of Chinese, mixed-language, or code-switching prompts
- **Low sophistication**: mostly direct requests ("How to make X?") with no social engineering
- **Narrow harm taxonomy**: concentrated in a few categories, missing many real-world attack vectors
- **Small and static**: community has memorized them — models may be specifically trained against these exact prompts

Our datasets address all of these:

| Dimension | Our dataset | mlabonne/harmful_behaviors |
|---|---|---|
| **Languages** | English + Chinese + mixed | English only |
| **Sophistication levels** | 4 levels (direct → socially-engineered) | 1 level (direct) |
| **Harm categories** | 12 categories | ~3-4 categories |
| **Format diversity** | QA, roleplay, academic, narrative | Single format |
| **Design methodology** | Adversarial red-teaming with matched benign counterexamples | Community-sourced |

The documented metadata fields are `category`, `language`, `sophistication`,
`format`, `style_family`, and `design_goal`. The benign datasets were designed
as **matched counterexamples**: topically similar, policy-compliant prompts.
Any quality advantage requires a matched evaluation rather than following
automatically from this design. Historical documents disagree on category
counts; the original artifacts are needed to verify the exact taxonomy.
